# 验证、验收与已知限制

当前交付环境是 Windows；没有在 Ubuntu / RTX 5080 上执行预训练模型完整推理。依赖解析、离线控制流程测试和真实目标机器验收是不同证据。任何单元测试通过数量都不能替代本机模型验收报告。

## 验证层级

| 检查 | 能验证 | 不能证明 |
| --- | --- | --- |
| 应用单元测试和离线部署替身 | 时轴、契约、脱敏、目录保护、恢复、报告及模拟编排 | Ubuntu 包安装、真实驱动、模型质量 |
| `scripts/doctor.py` | 实际依赖导入、解码、CUDA 算子、NumPy bridge、Ollama 存在 | 预训练权重加载及整段推理 |
| `scripts/smoke_models.py` | ClearVoice 模型代码、NumPy 接口和随机权重 CUDA 前向 | 预训练模型的分离效果 |
| `scripts/acceptance.py` | 真实录音完整推理、模型执行证据和产物检查 | 人物归属和纪要语义全对 |
| 人工回听和标注对照 | 串音、漏声、归属、CER、事实及引用是否支持结论 | 未测试场景中的普遍准确率 |

一键入口依次运行目标机器检查与录音验收，结束时显示报告。完整安装、升级、重启恢复和日志定位见 [部署](deployment.md)。独立使用验收脚本：

```bash
# 从项目根目录执行，先安装环境并配置 HF_TOKEN / Ollama。
.venvs/app/bin/python scripts/doctor.py
.venvs/separate/bin/python scripts/smoke_models.py --device cuda:0
.venvs/app/bin/python -u scripts/acceptance.py ./recording.wav
```

真实录音验收要求 30–60 秒左右、两人分别独说并有数秒重叠。它检查四个 worker 都确实执行且请求 CUDA、分离任务非空、两条音轨与原时轴等长、双人非空文字、字词时间戳及有效的纪要引用，并记录 `gpu.csv`。没有重叠或纪要失败都不能通过。`--reference-1` / `--reference-2` 可提供清晰参考；`--run-dir` 可复核已有产物结构，不能代替新一轮 GPU 执行证明。

部署报告中的 `PASS` 与退出码 0 表示自动执行和产物检查通过；`quality_status` 仍为 `PENDING_MANUAL_REVIEW`。驱动安装后的 `REBOOT_REQUIRED` 返回 20，需要手动重启再运行；其他非零退出码应先查看报告列出的失败阶段日志。

## 质量验收与限制

先准备 30–60 秒的双人中文录音，包含每人几秒单独说话和一个短重叠片段。执行带纪要的完整任务，回听两条音轨并检查：人物是否交换、重叠处是否漏声、文字是否归对人物、时间戳是否落在正确位置、纪要引用是否支持对应结论。再逐步增加长录音、噪声、方言、相似声线和混响。

| 检查目标 | 方法 |
| --- | --- |
| GPU 与安装 | `doctor.py`，终端运行时观察 `nvidia-smi` |
| 分离效果 | 回听串音、漏声、音色和电平；有干净参考轨时计算 SI-SDRi |
| 转写与人物归属 | 人工标注一小批音频，统计 CER 与人物归属错误 |
| 模型对照 | 固定录音、ASR 和分段配置，每次只换一个后端，记录耗时和峰值显存 |
| 应用逻辑 | 在 app 环境安装 pytest，运行 `python -m pytest -q`；这些测试不代替模型推理 |

这是离线开发 MVP，支持恰好两位说话人，不提供实时流式处理、多麦空间信息利用、降噪前端或自动人物命名。它依赖人物分段检测出的重叠；漏检的重叠不会被分离。单人区间从混音直接归轨，背景声仍可能保留。

ClearVoice 上游会对分离来源做 RMS 电平归一化，因此两条轨的绝对响度、相加后的混合波形不保证与原始录音一致。浮点 WAV 保留模型电平；播放或导入剪辑软件后仍应检查峰值。分块拼接也可能存在边界音色变化。本版 16kHz 音轨适合语音研发，不承诺高保真录音棚音质。

人物匹配 `margin` 是两种声道排列的平均余弦分数之差，不是准确率或校准后的置信度。相似声线、短句和持续重叠可能仍然归错人物，`uncertain` 仅提供复核提示。

若显存不足，先关闭其他 GPU 程序，将 `[pipeline].separation_chunk_seconds` 降至 6–8 秒，ASR 改为 0.6B 或关闭 aligner。默认分离块长加两侧上下文必须不超过 20 秒，以避免 ClearVoice 内部分块导致未跟踪的人物交换。单卡顺序运行有助于控制显存，但不能保证所有录音都在固定显存内完成。

模型和代码各有上游许可与访问条件，相关链接见 [模型后端](model-backends.md)与 `requirements/`；项目不会把模型权重打包进下载 ZIP。

## 兼容性复查：0.1.1

- TorchCodec 固定为 PyPI CPU 解码版，修复 CUDA 后缀 wheel 无法从默认索引安装的问题；重复安装也会修正已有 CUDA Codec 环境。
- ClearVoice 使用官方 NumPy 接口，绕过文件接口对输入电平的额外处理；加载时严格核对全部模型张量，拒绝部分随机权重。上游仍有逐来源 RMS 归一化，不能据此恢复每个人的原始绝对音量。
- SepFormer 的缓存目录按模型标识隔离，防止更换模型后沿用旧缓存。
- 五套 Ubuntu 24.04 / x86_64 / Python 3.12 锁定依赖图已重新解析，检查了 Linux wheel 可用性。
- Windows 上已实际安装 Torch 2.8 CPU 与 ClearVoice 0.1.2，运行真实模型代码的随机权重前向、NumPy API 与解码测试；完整架构与官方 checkpoint 元数据中的 1099 个张量形状一致。未下载完整 checkpoint，未在 Ubuntu / RTX 5080 上执行预训练模型推理。

## 一键部署脚本复查：0.1.4

本次围绕首次安装、重复运行、驱动重启恢复、HF_TOKEN 脱敏及失败报告做了代码审查、真实本地子进程测试和外部服务模拟。0.1.4 发布包同时整合了从 0.1.3 保留旧目录升级的入口。

### 升级入口与报告显示

`deploy_ubuntu.sh --upgrade --zip ... --audio ...` 交互选择旧目录、新目录；`--old-directory` 和 `--destination` 可预设路径，用于失败或重启后的原目录恢复。升级仍使用 0.1.4，不修改版本号。

缓存 helper `scripts/upgrade_cache.py` 验证路径并生成独立报告：新目录尚无 HF 缓存时链接旧项目默认缓存；新目录已有独立缓存时保留并说明；旧缓存不存在时报告按需下载。旧版源码、配置、虚拟环境及历史结果保留，新版另装环境。ClearVoice 用户缓存和同一个 Ollama 服务中的模型照常复用。报告明确列出缓存实际目标和保留要求，防止升级后误删依赖目录。

入口结束时直接显示本次 Markdown 报告，并明确打印完整报告及失败阶段日志的绝对路径。编排未启动的早期失败使用 bootstrap 报告；未生成的录音验收报告不显示为已通过。

升级相关回归覆盖目录隔离、默认缓存链接、重复运行、已有新缓存保留、失败时报告保存及源 ZIP 包含 helper/测试。具体测试结果以本次运行输出为准；这些离线测试不代表目标机器 GPU 推理通过。

### 已修复的部署恢复问题

| 场景 | 发现的问题 | 修复和回归验证 |
| --- | --- | --- |
| 首次安装中断 | `pyvenv.cfg` 已写入但 Python/pip 尚未创建，重复运行永久失败 | 补齐部分创建的 venv，缺 pip 时 ensurepip；真实 Bash 执行离线 Python/pip 替身验证，保留缓存和已有文件 |
| 重复运行 | 只测了单个 helper，缺少整个编排顺序和失败后恢复验证 | 模拟机器上跑完整编排：首次安装、第二次复用模型和缓存、HF 失败后重跑；每次独立报告，旧报告字节不变 |
| Ollama 首装恢复 | 安装中断可留下程序但没有服务；长下载后后台 sudo 重新提示密码可能卡住 | 检查服务 LoadState，缺失时修复安装；仅本次安装使用非交互 sudo 包装及定时续期，授权失效立即停止；不覆盖 masked 服务 |
| 驱动重启恢复 | 仅凭驱动命令退出码就认定安装完成 | 额外检查推荐 open 包的 dpkg 状态；仅 installed 时原子写 boot ID 标记；模拟同 boot 不重复安装及新 boot 恢复完整验收 |
| 凭证脱敏 | 顶层日志已清洗，但 worker 自写日志、异常和 JSON 仍可保留 token | worker 双流和父级原生输出统一脱敏；验证普通输出、os.write 原生 stderr、拆分写入、异常 traceback、错误 JSON 与自定义 token_env |
| JSON/Markdown 报告 | 先 JSON 编码再替换可能漏掉带转义字符的凭证；Markdown 路径使用未清洗原值 | 先递归清洗结构化值，再编码；完整 Markdown 清洗；测试引号、反斜杠和嵌套证据 |
| 极早失败 | 空/根目标路径、无法创建日志目录及 Python 初始化异常可能没有最终报告 | 日志 fallback、明确失败原因、独立初始化失败报告；保留旧报告，不覆盖历史验收 |
| 安全输入与中断 | getpass 无法禁用回显时可能回退明文输入；清理期间再中断可跳过报告；仅终止 shell 时未通知 runner | 禁止 getpass 明文回退；入口转发终止信号并等待本次 runner 清理；清理期间屏蔽重复信号并保证最终报告落盘 |
